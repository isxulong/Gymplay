# EXP-003 · 数字与指路牌必须能被他人重建

- 状态：现行｜起始 v0.3.3（2026-11-06，同一类错连犯两次）

## 背景

三起事故，共性是「写下来的东西，下一个人接不住」。

### 其一：数字来自形状不合法的对象

给出撤销条目的字节数 `44,644 / 68,212`，用来论证字节护栏的取值。复查发现探针的 `pre` / `post` 是 **object**，而真实 `UndoEntry` 要求两者为 **string**（字段要求见 `src/app/undo-store.ts:98` 的 `isUndoEntry`）。

数值本身可复算，但它是「一个不是撤销条目的对象」的字节数。成员复现不出来并拒绝引用，改用自己的合法构造——**他是对的**。要强调的是：这两个数字与编码侧的 `KEY_CHAR_MAX = 8192`（`src/core/config/codec.ts:55`）**无关**，撤销护栏常量是 `UNDO_ENTRY_MAX_BYTES = 64 * 1024`（`src/app/undo-store.ts:27`）。这里出问题的是「用形状不合法的对象去论证一个阈值」，不是「8192 建在了错误读数上」。

### 其二：指路牌指向不存在的对象，同一个错犯两次

先有注释引用 `node artifacts/bench-4c.mjs`——该脚本在仓库里不存在。

修这个 P1 时，注释改成「原始测量过程与输出记录见 v0.3.3 验证日志『第 6 次追加』的 4-c 段」——而该章节**也不存在**（日志实际只有第 11 至 25 次追加）。**修复动作自己制造了更糟的悬空引用**：原来只是「不精确」，改完变成「指向虚空」，读者按指引翻不到任何东西。

### 其三：「零命中」的检索会自污染

返工报告称「全文检索 `bench-4c` / `斜率` 均无命中」。

这句话写下即为真，但**记录它的文字本身成了新的命中**：

```bash
sed -n '1,1105p' log.md | grep -c "bench-4c"   # 2  ← 冻结在讨论之前
grep -c "bench-4c" log.md                      # 6  ← 全文件，多出的 4 处全是事后讨论"它没命中"的文字
```

所以「全文检索 X 均无命中」这种表述，在任何讨论过它的文档里都必然自证为假。

## 做法

### 1. 每个数字写成「构造条件 + 读数 + 复测方式」

合格样本就在 `src/core/config/codec.ts:35-53`。它写明了段数 300、段 id 为 base36 六位补零、`start = i×10`、`rate` 按九档循环、`label = '汉'.repeat(15)`、`filename`、`duration`、`loop`、`meta`，再给出读数与换算（`1,048,576 / 39,096 ≈ 26.82`）与复测方式。

反面是它替换掉的那组：「5,976 字符 / 41,562–50,562 B」——没有构造条件，**按描述无法在仓库现存代码里重建**（`tests/unit/core/config/p10-url-length.test.ts` 的 `buildConfig` 与 `probe/` 下的长度探针都复现不出）。

### 2. 造数据前，先让探针的产物过一遍真实校验

```bash
grep -n "export function isUndoEntry" src/app/undo-store.ts   # → :98
```

按它的字段要求构造测试对象，而不是随手写个 `{pre: {}, post: {}}`。

### 3. 写下任何「见 X」「详见第 Y 节」当场解析

```bash
test -f artifacts/bench-4c.mjs || echo MISSING_SCRIPT          # 脚本存不存在
grep -c "^## 第 " log.md                                        # 章节总数（用标题锚点，别用全文匹配）
```

**注意这里**：`grep -o "第 [0-9]* 次追加" log.md | sort -u -V` 看着像在统计章节，实际会**把正文里引用章节的文字也数进去**——实测它输出 16 条，第一条就是「第 6 次追加」（那是讨论悬空引用的句子，不是章节）。这正是本条要防的自污染，用 `^## 第 ` 这个标题锚点才准（实测 15 条）。

解析不到就删掉该引用，或如实写「该测量无留痕」，并指向仓库里**真有的**等价判据（本例是 `tests/unit/core/config/codec.test.ts` 的 4-c 用例）。

### 4. 用「零命中」当证据时，先冻结范围并写进结论

写「截至第 24 节前，`斜率` 零命中」，而不是「全文零命中」。否则读者照同一命令重跑，会得到不同的数字，然后开始怀疑你在造假。

## 后果

- **判据失去依据**：阈值建在无法重建的读数上，换机器、换配置后没人能判断它是否仍成立，只能盲猜。
- **注释比它要修的问题更糟**：从「不精确」降级为「指向虚空」。
- **「无命中」写进报告即自证其假**：读者重跑一次就能推翻，连带整份报告的可信度一起塌。

## 边界

- 「冻结范围」依赖人工指定行号，日志追加后需同步更新——这是本条自身的弱点，它没法自动化。
- 探针形状问题只核对了 `UndoEntry` 一个实例，其它探针是否有同类问题未查。
- 本条不负责「数字该不该写」，只负责「写了之后别人能不能重建」。
