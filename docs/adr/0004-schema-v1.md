# ADR-004 · 配置 Schema v1（终版 · 正式冻结）

- 状态：**已冻结（M0，2026-11-02）**
- 依据：《综合方案修订定稿 v2》§2.4（字段级冻结）、《工程蓝图》§5

## 冻结声明

> **Schema v1 自 M0 出口起正式冻结。** v1 尚未对外发布过密钥，本次定稿直接改 v1、不触发升版；
> 冻结后一切改动按下方「版本演进五条」执行。字段级定义以《综合方案修订定稿 v2》§2.4 表为唯一权威口径，
> 本文件不复述字段表，代码侧单一事实源为 `src/core/config/schema.ts`。

## v1 要点（相对蓝图原稿的修订）

- `video.type` 收窄为仅 `"local"`（url/hls 枚举移出 MVP）；
- `segments[].inQueue` 新增（缺省 true；false = 取消勾选，配置保留、不进播放队列）；
- `sequence` 语义重定义：队列顺序定义、可重复引用；播放队列 = sequence 过滤 inQueue=true；
  空数组或全部 inQueue=false = 队列空 = 播放禁用（原「空数组=按定义顺序全播」缺省**废除**）；
- `loop.mode` 由 enabled 布尔改为三态：`"off" | "queue" | "segment"`；
  `loop.count` 仅 mode="queue" 有效，缺省或 0 = 无限循环；
- 所有时间单位为秒（number，毫秒精度）。

## 版本演进五条

1. **v 单调递增**：解码器按 v 查迁移链，旧版本逐级升到当前版后再校验（`migrate.ts` 注册表）。
2. **前向宽容**：不认识的字段一律忽略并保留警告日志，不校验失败。
3. **后向拒绝**：v 大于当前支持版本 → 明确报错「该密钥由更新版本生成，请升级应用」，绝不静默猜解析。
4. **升版纪律**：新增可选字段、收紧文案类约束 → 不升 v；改变字段语义、删字段、改类型、收紧会导致存量密钥失效的数值约束 → 升 v 并登记迁移函数。
5. **与应用版本解耦**：Schema 的 v 与 App 的 SemVer 两套版本，CHANGELOG 分开记录。

## 编码管线与载体（P10 结论入档）

规范化 JSON（键名字典序、UTF-8、无空白）→ pako deflate（level 9，**pako 锁定 1.0.11**）→ base64url → `#c=` hash。

- **判定线统一 1500 字符**（消除原 P10 判 2000 / R10 降级 1500 的双阈值矛盾）。
- P10 实测：50 段配置密钥 1359 字符（在线内）、80 段 1911 字符（越线）→ **URL 密钥适用 ≤50 段；>50 段走 .json 导出/导入降级**（M3 接线 UI）。
- 两种载体共享同一数据模型与同一校验链：`exportConfig(cfg): Blob` / `importConfig(file): Result<PlayerConfig>` 已在 L3 预留实现（`codec.ts`），M3 直接接线、不改 L3 接口。
- 受控变更点：`segments[].rate`（0.5~4）——P4 收窄时走连锁变更路径；P4 听感口径（0.5~2x 跟练区、3x~4x 跳过区、preservesPitch 默认开启）见 ADR-001。
