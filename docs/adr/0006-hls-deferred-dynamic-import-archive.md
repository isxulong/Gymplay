# ADR-006 · HLS 砍出 MVP，动态 import 技巧存档备用（终版）

- 状态：已定稿（M0，2026-11-02）
- 依据：《综合方案修订定稿 v2》§0.4（唯一收窄项）、§2.1；《工程蓝图》§2.6

## 决策

MVP 无 HLS、无直链：`video.type` 仅 `"local"`，hls.js 移出依赖白名单（运行时依赖仅 pako，见 ADR-003）。

## 理由

需求稿（上游授权产物）「不做清单」第 6 条已将直链 mp4 移出 MVP 并冻结配套话术；蓝图原稿单方面把
url/hls 放回 Schema v1 与 M3 属范围蔓延，定稿按需求稿口径纠正。本地文件是 v1 唯一视频源
（上游「本地文件一等公民」结论强化）。

## 存档备用的设计技巧：动态 import 按需加载

日后 HLS 加回时复用（升版纪律评估后）：

- hls.js 体积（min+gzip 约百 KB 量级）若进主 bundle 直接威胁 <1MB 硬约束，必须 **动态 import**、
  仅当用户加载 HLS 源时才拉取，CI 体积门禁对 hls.js chunk 单列监控、不计入主 bundle；
- iOS Safari 原生支持 HLS 时优先走原生、不加载 hls.js；
- Schema 侧加回 `video.type: "url" | "hls"` 属字段语义变更 → 按版本演进五条升 v 并登记迁移函数。

## 旁证（P9）

HEVC 在目标设备可直读（hev1 / hvc1 双样本实测出画面出声），本地文件路线对编码兼容性的
风险已实证消解——「本地唯一源」决策不引入转码引导负担（仅提示，见 ADR-001 P9 行）。
